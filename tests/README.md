# Telegram Invite Bot 测试文档

本文档描述了 Telegram Invite Bot 的测试策略和测试覆盖范围。

## 测试架构

测试使用 Bun 内置的测试框架（`bun:test`）和 expect 断言库。测试分为以下几类：

1. **单元测试** - 测试单独的组件和功能
2. **集成测试** - 测试多个组件的集成和交互

## 测试覆盖范围

### 工具类测试

* `linkGenerator.test.ts` - 测试邀请链接生成功能
  * 验证链接生成的唯一性
  * 验证 URL 格式化正确性

### 存储服务测试

* `storage.test.ts` - 测试存储服务的基本功能
  * 用户数据的保存和读取
  * 邀请链接的关联和查询
  * 邀请统计和排名计算

### 集成测试

* `integration.test.ts` - 测试完整邀请流程
  * 用户生成邀请链接
  * 用户通过邀请链接加入
  * 统计邀请数量
  * 计算和查询用户排名

## 测试数据

测试使用 `MockStorageService` 作为存储层的模拟实现，使用内存中的数据结构而不是真实的键值存储。这允许测试不依赖于外部服务就能进行。

## 运行测试

### 运行所有测试

```bash
bun test
```

### 运行特定测试

```bash
# 运行存储服务测试
bun test:storage

# 运行链接生成器测试
bun test:link

# 运行集成测试
bun test:integration
```

## 测试覆盖率

要生成测试覆盖率报告，请运行：

```bash
bun test --coverage
```

## CI/CD 集成

在持续集成流程中，测试应当在构建和部署之前运行，以确保代码质量。如果任何测试失败，则应中止部署流程。
